Unit 5 Core Architecture

1. Elementary Quadratic Sorts

  • Bubble Sort: Repeated adjacent swaps; bubbles largest unsorted item to right. Optimized with swap flag achieves O(N) best-case time.
  • Selection Sort: Finds minimum in unsorted suffix, performs single swap per pass. Comparisons strictly N(N-1)/2 always! Best-case is O(N^2). Minimum swaps: at most $N-1$.
  • Insertion Sort: Inserts current element into sorted left prefix by shifting. Best case O(N) on sorted data (1 comparison/elem, 0 shifts). Online & highly efficient on small arrays.

2. Divide & Conquer Paradigms

  • Merge Sort: Divides array into halves recursively ($T(n) = 2T(n/2) + \Theta(n)$). Guarantees O(N log N) in all cases. Auxiliary space is O(N) (not in-place). Stable.
  • Quick Sort: Selects pivot, partitions array ($A[k] \le P$ left, $> P$ right). Average time O(N log N), In-place aux space O(log N) stack.
  • Quick Worst-Case: Occurs when pivot is extremal (already sorted + naive pivot) → recursive depth $N$, runtime degrades to O(N^2)! Unstable.

3. Stability & Comparison Limits

  • Stability Invariant: Relative order of equal keys is preserved. Stable: Bubble, Insertion, Merge, Timsort. Unstable: Selection, Quick, Heapsort.
  • Decision Tree Model: Comparison-based sorting must distinguish between $N!$ permutations. Minimum comparisons: $\lceil \log_2(N!) \rceil = \mathbf{\Omega(N \log N)}$.
  • Non-Comparison Sorts: Counting Sort, Radix Sort break $\Omega(N \log N)$ lower bound by exploiting numerical digit properties.

4. Python Timsort & CUET Traps

  • Python Built-in Sort: Uses Timsort (hybrid of Merge Sort and Insertion Sort). Worst case $O(N \log N)$, Best case $O(N)$ on partially sorted data, Space $O(N)$.
  • list.sort() vs sorted(): list.sort() sorts in-place, returns None. sorted(iterable) returns a fresh new list.
  • Trap Alert: "Selection sort best case is $O(N)$" (FALSE, always $O(N^2)$ comparisons). "Insertion sort pass $k$ gives final positions" (FALSE, only locally sorted prefix).
