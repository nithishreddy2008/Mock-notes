SEARCHING & HASHING

Key Lookup Paradigms

1. Linear Search (Sequential)

  • Mechanism: Scans array sequentially from index $0$ to $N - 1$.
  • Preconditions: Zero preconditions. Operates on unsorted lists.
  • Complexity: Best $O(1)$, Worst $O(N)$, Average $O(N)$.
  • Use Case: Small collections or unordered dynamic datasets.

2. Load Factor & CPython Dict Internals

  • Load Factor ($\lambda$): $\lambda = N / m$ (Occupancy density metric).
  • Rehashing: Table doubles when $\lambda > 0.66$; re-computes all hash indices.
  • SipHash Algorithm: Cryptographic hash preventing collision DoS attacks.
  • Compact Dict Layout: Dense entry array + sparse index table (saves $30\%$ RAM).

3. Binary Search (Divide-and-Conquer)

  • Precondition: Strictly sorted array ($O(1)$ random access).
  • Range Halving: $mid = low + (high - low) // 2$. Halves search space.
  • Complexity: Best $O(1)$, Worst $O(\log N)$, Average $O(\log N)$.
  • Recurrence: $T(N) = T(N/2) + O(1) \implies O(\log N)$.

4. Hash Function Architectures

  • Division / Modulo: $h(k) = k \bmod m$, where $m$ is a prime number.
  • Mid-Square: Square key $k^2$, extract middle $r$ digits ($m = 10^r$).
  • Folding Method: Partition key into equal parts, sum parts, modulo $m$.
  • Multiplication Method: $h(k) = \lfloor m (k A \bmod 1) \rfloor$, $A \approx 0.618$.

5. The Seven Fatal CUET Traps

  • Unsorted Binary Search: Yields invalid results without prior sorting.
  • Midpoint Overflow: (low + high) // 2 vs low + (high - low) // 2.
  • Tombstone Erasure Bug: Deleting in open addressing requires tombstones.
  • Primary Clustering: Long occupied blocks degrade linear probe to $O(N)$.

6. Collision Resolution Strategies

  • Separate Chaining: Linked list buckets at each slot; $\lambda$ can exceed 1.
  • Linear Probing: $(h(k) + i) \bmod m$; primary clustering hazard.
  • Quadratic Probing: $(h(k) + c_1 i + c_2 i^2) \bmod m$; reduces clustering.
  • Double Hashing: $(h_1(k) + i \cdot h_2(k)) \bmod m$; optimal scatter.
