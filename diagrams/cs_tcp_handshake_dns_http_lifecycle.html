End-to-End Web Transaction Lifecycle: DNS, TCP & HTTP Execution

CUET UG Computer Science (Code 308) · Complete Chronological State Machine from Domain Resolution to Socket Teardown

RFC 793 · RFC 1035 · RFC 2616
1
DNS Resolution
Hierarchical Name Lookup
Client → Local DNS UDP 53
Local → Root (".") Referral
Local → TLD (".org") Referral
Local → Auth DNS IP Match
Auth → Client Resolved IP
CUET Invariant: Standard queries execute over lightweight UDP Port 53. If packet exceeds 512 bytes or during zone transfers, DNS switches to TCP 53.
2
TCP 3-Way Handshake
Connection Establishment
Client → Server SYN (seq = x)
Server → Client SYN-ACK (seq=y, ack=x+1)
Client → Server ACK (ack = y+1)
★ Socket Established ★
CUET Invariant: Handshake synchronizes 32-bit sequence numbers. The ACK number is always Next Expected Byte ($\text{ack} = \text{seq} + 1$).
3
HTTP / TLS Data Exchange
Application Payload Transfer
Client → Server TLS Handshake
Client → Server HTTP GET /index.html
Server → Client HTTP/1.1 200 OK
Server → Client HTML/CSS Payload
CUET Invariant: HTTP is stateless. HTTPS runs over Port 443 with TLS encryption. Status codes: 200 (Success), 301 (Redirect), 404 (Not Found), 500 (Server Error).
4
TCP 4-Way Teardown
Graceful Socket Close
Client → Server FIN (Active Close)
Server → Client ACK (ack = fin+1)
Server → Client FIN (Passive Close)
Client → Server ACK → TIME_WAIT
CUET Invariant: Teardown requires 4 segments because TCP is full-duplex; each transmission direction must be terminated independently.
Protocol Milestones: DNS Resolution (UDP 53) → TCP 3-Way Handshake → HTTPS/TLS Data Exchange (Port 443) → TCP 4-Way Teardown
