Grouping, Joins & Sets

📊 Aggregate Functions & NULL Semantics

  • COUNT(*): Evaluates total row count of relation/group, including rows containing NULL values.
  • COUNT(column): Counts only non-null values. COUNT(DISTINCT col) counts unique non-nulls.
  • SUM() & AVG(): Computes arithmetic sum and average of non-null numeric attributes.
  • The AVG() Trap: AVG(col) = SUM(col) / COUNT(col), dividing strictly by non-null count!
  • MIN() & MAX(): Finds extremes for numbers, dates, and alphabetical strings (ignoring NULL).

📁 Partitioning & Group Filtering

  • GROUP BY: Partitions rows into buckets based on identical column values. Multi-column grouping supported.
  • Grouping Column Rule: Every non-aggregate attribute in SELECT must be included in GROUP BY!
  • NULL in GROUP BY: Multiple rows containing NULL are consolidated into a single summary group.
  • HAVING Clause: Filters summary partitions after grouping. Supports aggregate predicates (HAVING COUNT(*) > 2).
  • Execution Order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY.

🔗 Relational Joins & Outer Joins

  • INNER JOIN: Combines matching tuples on predicate (ON R.id = S.id). Dangling tuples discarded.
  • NATURAL JOIN: Equi-join on all common attributes; automatically eliminates duplicate shared columns!
  • CROSS JOIN: Unrestricted Cartesian product: Degree = n1 + n2, Card = m1 × m2.
  • LEFT OUTER JOIN: Preserves all rows of Left table; fills unmatched Right attributes with NULL.
  • RIGHT OUTER JOIN: Preserves all rows of Right table; fills unmatched Left attributes with NULL.
  • FULL OUTER JOIN: Preserves unmatched rows from both tables (emulated via UNION in MySQL).

🧩 Set Operations & Nested Queries

  • Union Compatibility: Identical degree and pairwise compatible data types required across queries.
  • UNION: Combines results and eliminates duplicate rows via internal sorting.
  • UNION ALL: Combines results without eliminating duplicates (much faster performance!).
  • INTERSECT & EXCEPT: Returns shared tuples (Intersection) or tuples unique to query 1 (Difference).
  • Subqueries: Single-row (=, <, >) vs Multi-row (IN, NOT IN, ANY, ALL, EXISTS).
