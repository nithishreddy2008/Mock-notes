Data Definition (DDL) vs Data Manipulation (DML), Table Integrity Constraints & Transaction Reversibility

DDL Data Definition Language
CREATE TABLEDDL
Defines new relations, attribute names, data types, and declarative column/table constraints.
ALTER TABLE (ADD / MODIFY / DROP)DDL
Modifies existing table schema: adds new attributes, modifies data types/widths, drops columns or constraints.
DROP TABLE vs TRUNCATE TABLEDDL
DROP: Destroys schema + data entirely. TRUNCATE: Purges all rows instantly; retains the empty table schema. Both auto-commit!
DML Data Manipulation Language
INSERT INTODML
Appends new tuples into a relation. Requires matching data types; omitted non-null columns without defaults trigger errors.
UPDATE ... SET ... WHEREDML
Modifies existing attribute values in matching tuples. Omitting the WHERE clause updates every tuple in the table!
DELETE FROM ... WHEREDML
Removes specific tuples satisfying WHERE predicate. Omitting WHERE empties the table row-by-row. Transactional (rollback allowed).
CONSTRAINTS Relational Integrity Enforcers
PRIMARY KEYNOT NULL + UNIQUE
Uniquely identifies each row. Exactly one per table. Strictly prohibits duplicate values and NULL entries.
FOREIGN KEY (REFERENCES)Referential
Links child attribute to parent Primary Key. Enforces referential integrity (ON DELETE CASCADE, SET NULL, RESTRICT).
UNIQUE, NOT NULL, CHECK, DEFAULTDomain
UNIQUE: Prohibits duplicates (allows multiple NULLs). CHECK: Enforces custom ranges. DEFAULT: Supplies fallback value.
