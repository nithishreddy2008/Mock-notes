Unit 7 Core Architecture

1. DBMS Foundations & Architecture

  • File System Drawbacks: Data redundancy, inconsistency, lack of atomicity, uncoordinated concurrent access, poor security.
  • Three-Level Architecture: Physical (disk representation), Conceptual (logical tables/constraints), External (user views).
  • Data Independence: Physical (modify disk without altering logic) vs Logical (modify schema without breaking apps).
  • ACID Properties: Atomicity (all-or-nothing), Consistency (integrity valid), Isolation (concurrent safety), Durability (persisted).

2. Relational Model & Keys Hierarchy

  • Model Invariants: Relation (Table), Tuple (Row), Attribute (Column), Domain (atomic permitted values).
  • Degree vs Cardinality: Degree = Number of Columns ($n$); Cardinality = Number of Rows ($m$).
  • Super Key → Candidate Key: Candidate Key is a minimal super key uniquely identifying tuples.
  • Primary & Alternate Keys: Chosen candidate key is Primary Key (cannot be NULL). Remaining candidate keys are Alternate Keys.
  • Foreign Key: Attribute referencing PK in parent table. Enforces Referential Integrity. Can be NULL!

3. Relational Algebra Operations

  • Selection ($\sigma_C$): Horizontal filter of tuples satisfying condition $C$. Degree unchanged; Cardinality $\le m$.
  • Projection ($\pi_L$): Vertical column filter of list $L$. Strictly eliminates duplicate tuples. Degree $= |L|$.
  • Union Compatibility: Requires identical degree and compatible attribute domains. Required for $\cup, \cap, -$.
  • Cartesian Product ($R \times S$): Unrestricted pairs. Degree $= n_1 + n_2$ (Additive); Cardinality $= m_1 \times m_2$ (Multiplicative).

4. Relational Joins & Integrity Rules

  • Theta Join ($R \bowtie_\theta S$): Selection applied on Cartesian product: $\sigma_\theta(R \times S)$.
  • Natural Join ($R \bowtie S$): Equi-join on common attributes, automatically projecting out duplicate column copies.
  • Natural Join Degree: $\text{Deg}(R \bowtie S) = n_1 + n_2 - k$ (where $k$ is number of shared attributes).
  • Integrity Constraints: Entity Integrity (PK $\ne$ NULL); Referential Integrity (FK matches PK or NULL); Domain Integrity.
