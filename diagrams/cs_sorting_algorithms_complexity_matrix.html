1 Elementary Sorting Mechanics
Bubble Sort (Sinking Sort) STABLE
Compares adjacent pairs $(j, j+1)$ and swaps if out of order. Bubbles largest element to end each pass. With early termination flag, achieves $O(N)$ best case on sorted inputs.
Selection Sort UNSTABLE
Scans unsorted prefix to find absolute minimum; performs exactly one swap per pass. Performs strictly $N(N-1)/2 = O(N^2)$ comparisons in all cases (best, average, worst).
Insertion Sort STABLE
Maintains sorted subarray on left; shifts larger elements rightward to insert incoming key. Extremely fast ($O(N)$) for nearly-sorted data and online streaming input.
2 Advanced Divide & Conquer
Merge Sort STABLE
Divides array into halves, recursively sorts, then merges two sorted subarrays. Strictly $O(N \log N)$ in all cases. Requires $O(N)$ auxiliary buffer memory.
Quick Sort UNSTABLE
Partitions array around a pivot such that elements $\le$ pivot are left and $\ge$ pivot are right. In-place. Best/Avg: $O(N \log N)$; Worst: $O(N^2)$ on already sorted arrays.
Timsort (Python Standard) STABLE
Hybrid adaptive algorithm combining Merge Sort and Insertion Sort. Identifies natural ordered "runs". Powers Python's built-in `list.sort()` and `sorted()`.

CUET Fatal Trap: Selection Sort Best-Case Comparisons!
Many students mistakenly assume Selection Sort runs in $O(N)$ when the array is already sorted. In reality, Selection Sort always executes exactly $N(N-1)/2$ comparisons regardless of input ordering, because it must scan the entire unsorted subarray to confirm the minimum. Its best-case time complexity is strictly $O(N^2)$!
