Accounting Data Hierarchy in RDBMS Data Ladder
1. Bit / Byte 0 or 1; Byte represents single alphanumeric character (e.g. 'A').
2. Field / Attribute Smallest named unit of data: Voucher_No, Acc_Name, Amount.
3. Record / Tuple Collection of related fields for one transaction row (Voucher entry).
4. Table / Entity / File Set of records sharing identical structure: Accounts_Master, Journal.
5. Database Integrated collection of logically related accounting tables.
Relational Principle: In an RDBMS, rows are called Tuples and columns are called Attributes!
Relational Database Key Architecture Integrity Constraints
Primary Key
Attribute uniquely identifying each row in a table. MUST be Unique and CANNOT contain NULL values (e.g., Voucher_ID).
Foreign Key
Field referencing the Primary Key of another table, enforcing Referential Integrity between Ledgers and Vouchers.
Candidate Key
Any attribute or minimal set of attributes that qualifies to become a Primary Key (e.g., Account_Code, PAN_Number).
Alternate Key
Candidate keys not selected as the primary key. Serves as secondary unique identifier.
Entity Integrity Rule: Primary Key can NEVER accept a NULL value under any circumstance!
SQL Classification: DDL vs DML in Accounting Command Taxonomy
• DDL (Data Definition Language): Defines and modifies the structural schema of accounting tables.
   ▸ CREATE TABLE Ledgers (...), ALTER TABLE Vouchers ADD (...), DROP TABLE Temp_Audit.
• DML (Data Manipulation Language): Queries, inserts, updates, and deletes transaction data rows.
   ▸ SELECT (retrieves balances), INSERT INTO (posts new vouchers), UPDATE (edits narration), DELETE (removes unapproved draft entries).
CUET Question: Is SELECT a DDL or DML command? It is strictly DML (Data Manipulation Language)!
Practical SQL Query Model: Trail Extraction Query Execution
Extract all accounts with total debit vouchers exceeding ₹50,000 for FY 2024-25, sorted descending:
SELECT Account_Head, SUM(Debit_Amount) AS Total_Debit
FROM Voucher_Transactions
WHERE Transaction_Date >= '2024-04-01'
GROUP BY Account_Head
HAVING SUM(Debit_Amount) > 50000
ORDER BY Total_Debit DESC;
WHERE vs HAVING: WHERE filters individual raw rows; HAVING filters grouped aggregate values!
