1 Search Paradigms & Mechanics
Linear Search (Sequential) Unordered Data
Scans element-by-element from index 0 to $N-1$. Zero preconditions required. Best: $O(1)$ (target at index 0); Worst/Avg: $O(N)$ (target at end or absent).
Binary Search (Divide-and-Conquer) Strictly Ordered Data
Compares target with midpoint $mid$. Halves search space each iteration: $[low, mid-1]$ or $[mid+1, high]$. Best: $O(1)$; Worst/Avg: $O(log N)$.
Hash Table (Direct Key Addressing) Direct Index Access
Maps keys to indices via hash function $h(k)$. Best/Avg: $O(1)$ constant time lookup. Worst: $O(N)$ if all keys collide into a single bucket.
2 Hash Functions & Collisions
Division / Modulo Method h(k) = k mod m
$m$ chosen as a prime number not close to a power of 2 to ensure uniform scatter across buckets.
Collision: Separate Chaining Open Hashing
Each table slot holds a linked list bucket. Keys with identical hashes are appended to the bucket chain.
Collision: Linear Probing Closed Hashing
Probes sequentially: $(h(k) + i) mod m$. Suffers from Primary Clustering (long contiguous blocks of occupied slots).
Collision: Quadratic & Double Hash Advanced Probing
Quadratic: $(h(k) + c_1 i + c_2 i^2) mod m$. Double Hashing: $(h_1(k) + i cdot h_2(k)) mod m$ eliminates clustering.

CUET Fatal Trap: Precondition Check for Binary Search!
Applying Binary Search on an unsorted list produces totally unpredictable and invalid results! If a list is unsorted, it must first be sorted ($O(N log N)$), which is only advantageous if multiple repetitive searches ($M > log N$) are performed. For a single one-off search, Linear Search ($O(N)$) is strictly faster than sorting + binary searching ($O(N log N)$).
