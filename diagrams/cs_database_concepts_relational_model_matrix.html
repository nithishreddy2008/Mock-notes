File System vs Relational DBMS
Dimension File System RDBMS
Redundancy High duplicate copies across isolated files. Controlled & centralized; normalized.
Inconsistency Updating one file leaves others outdated. Single source of truth prevents mismatches.
Concurrency File locks block simultaneous writes. ACID multi-user concurrency control.
Integrity Hardcoded validation checks in each app. Declarative constraints (PK, FK, CHECK).
Atomicity Partial crashes corrupt data. Transaction rollback / WAL guarantee.
Three-Schema Architecture:
• Physical / Internal: Disk storage, B-trees, indexing.
• Conceptual / Logical: Tables, attributes, entities, constraints.
• External / View: Customized user views and dashboards.

Relational Data Model Terminology
Formal Model Term: Common Table Analogy
Relation: Table
Tuple: Row / Record
Attribute: Column / Field
Degree: Number of Columns
Cardinality: Number of Rows
Domain: Set of Atomic Permitted Values
Cartesian Product Foundation:
Mathematically, a relation $R$ of degree $n$ is defined as a formal subset of the Cartesian product of $n$ attribute domains: $$R \subseteq D_1 \times D_2 \times \dots \times D_n$$

Keys Hierarchy & Integrity Constraints

Super Key

Any set of one or more attributes that uniquely identifies a tuple within a relation.

Candidate Key

A minimal super key (no proper subset can uniquely identify a tuple).

Primary Key

The chosen candidate key uniquely identifying tuples. Cannot contain NULL!

Alternate Key

Any candidate key not selected as the primary key ($AK = CK - \{PK\}$).

Foreign Key (Referential Integrity)

Attribute in child table that references the Primary Key of a parent table.
CUET Fatal Trap: Foreign Key NULL Value Rule!
Students assume foreign keys can never be NULL. FALSE! A foreign key can contain NULL values unless explicitly defined with `NOT NULL`. If non-null, every FK value must match an existing PK in the parent table!
