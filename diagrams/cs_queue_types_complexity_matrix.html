ENQUEUE (Rear) →
  • enqueue(item): Inserts element at Rear. Moves $Rear arrow.r Rear + 1$. Bounded queues check for Overflow.
  • dequeue(): Removes and returns element from Front. Moves $Front arrow.r Front + 1$. Checks for Underflow.
  • peek() / front(): Inspects front element without mutation.
  • is_empty(): Returns `True` if $Front == -1$ or $Front > Rear$.
  • size(): Calculates element count: $(Rear - Front + 1)$.
2 Queue Architectural Variations
Linear Queue Memory Drift Hazard
Pointer drift causes "False Overflow" when $Rear == Max-1$ even if front slots are empty after dequeues.
Circular Queue Ring Buffer / Modulo
Wraps pointers via $P = (P + 1) mod Max$. Full when $(Rear + 1) mod Max == Front$. Completely reuses reclaimed slots.
Double-Ended Queue (Deque) Bi-Directional
Inserts and deletes permitted at both ends. Subtypes: Input-Restricted (insert at 1 end, delete at 2) vs Output-Restricted (delete at 1, insert at 2).
Priority Queue Key-Driven Order
Elements dequeued based on priority key (min-heap or max-heap), regardless of arrival sequence.

CUET Fatal Trap: `list.pop(0)` Dequeue Performance!
Using Python's standard `list` for a queue with `s.append(x)` and `s.pop(0)` is a common textbook anti-pattern. `pop(0)` requires shifting all $N-1$ subsequent elements in physical RAM, costing $O(N)$ linear time! Production and CUET optimal implementations strictly require `collections.deque` (`popleft()` is strictly $O(1)$).
